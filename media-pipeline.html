Case study · Automation

One idea file in, one finished reel out.

A small HTTP service that renders video and synthesises voice, driven by n8n. No editor, no timeline, no manual export. The composition is a template and the data is a JSON file, so the same reel can be re-rendered for free when the numbers change.

  • 3service endpoints
  • 14composition templates
  • 318voices catalogued
  • −14LUFS, two-pass

Figure 1. One idea file in, one finished file out. Orchestration and rendering are separate services on purpose.

Why it exists

Three endpoints and one contract. /tts turns text into audio through a provider with a language guard and a free-first fallback chain. /render composes a scene graph from a template plus data. /mux puts voice, music bed and burned-in captions into one file. It exists because editing video by hand does not scale past the second idea.

How it works

  • Templates over editors. Each template is deterministic HTML/CSS, so a re-render is free and a design change is a diff, not a redo.
  • Language guard. If a requested voice cannot serve the requested language, the request is rejected at the edge. A silent wrong-language render is worse than a failure.
  • Cost is a header. Every response carries X-Media-Cost-Usd, duration and a JSON receipt naming which provider hop actually served it, so a fallback never hides a bill.
  • Audio done properly. Music is ducked under voice, then two-pass loudness normalisation to −14 LUFS / −1.5 dBTP. Off-the-shelf defaults are not good enough for platform playback.
  • Orchestration elsewhere. n8n owns scheduling, retries and delivery; the service stays stateless and stdlib-only, so it is cheap to run and trivial to replace.

Lessons learned

Coupled audio: loudness normalisation that respects a ducked bed, and captions that land on the beat rather than near it. Both are easy to fake and obvious when wrong.

And the boring one: verifying a render actually happened. A queued job that never fires looks identical to a job that succeeded, unless you check the artifact afterwards.

What I would do differently:

  • Pick the caption timing model before the third template, not after. Retrofitting it costs more each time.
  • Keep the service stateless from the first commit. Every piece of in-process state became a reason a retry behaved differently from a first run.
  • Screenshot every render, not just the final mux. The expensive failures were layout, not encoding.
